01

The core thesis

Two ideas drive everything else.

  • Code is better context than human-written documentation. The single best source of truth about how a library behaves is its source code, not its docs. Docs drift, omit edge cases, and are written for humans skimming — source is exact.
  • Less context beats more context. A model degrades as its context window fills. The goal is to give it just enough — the exact function, the exact constraint — not the whole codebase.

These reverse the prevailing 2024–2025 approach, which was to stuff the agent with everything: minifying entire codebases into XML, vector-indexing the whole repo with RAG. Modern models search well enough that you point them at the right place rather than pre-loading everything. The reversal is real and worth internalizing — the techniques here have roughly a six-month half-life.

02

The workflow

The whole thing is a loop that ends in a verifiable state. Each piece exists to keep context small and the end condition clear.

1
Plan first — for your accountability, not the agent's

Have the model generate a plan before it writes code. The value is that you can catch a too-large scope before any code exists. A model writing a plan doesn't account for its own context window; it dumps everything the task needs into one plan. When the plan looks big, push back: "break this into the smallest reviewable PRs you can."

2
Give it exact context, not documentation

Instead of pasting docs or letting the agent guess at an API, fetch the actual source of the dependency into the repo and tell the agent to reference it (see opensrc below). The agent finds the exact function — no guessing.

3
Generate the feature in a small PR

Small, single-purpose PR. Resist the urge to bundle.

4
Run an external review loop until it passes

A separate review agent scores the PR. Re-run the fix loop until the score clears your bar. The loop self-terminates on a defined end state — a passing score, a passing test — rather than running forever. This is Karpathy's "auto-research loop" applied to shipping code.

5
Restructure after the feature lands

Agents rewrite existing functions rather than reuse them, which accumulates duplicate code and makes future debugging harder. After a feature, run a pass that consolidates repeated logic into a reusable service layer. Cleaner structure is easier for the next session to pick up.

The model predicts the next token; it has no model of whether its decision is correct. Your judgment is the part that doesn't come in the box.

03

The verified tool stack

opensrc exact source as context ✓ vercel-labs

npx opensrc <package> clones a dependency's source into ./opensrc/ and adds a prompt block telling the agent the source is available for understanding how a package works internally, not just its types.

  • The podcast's auto-transcript renders it as "open source" — a homophone, not the license term.
  • Works beyond npm: pypi:requests, crates:serde, owner/repo. Relevant to Python / Rust / Lisp-adjacent work, not just JavaScript.
  • Usage: fetch the source, then tag the folder in your prompt and say "reference the codebase."
  • github.com/vercel-labs/opensrc
Greptile AI PR review + confidence score ✓ watch FPs

Indexes the whole repo into a semantic map, then reviews each PR with multi-hop investigation across files and git history. Every review gets a 0–5 confidence score based on issue severity, change complexity, and pattern fit.

  • v3+ runs on the Claude Agent SDK. The "loop until 5/5" workflow is legitimate.
  • Pricing early 2026: ~$30/user/month. Self-hostable in-VPC.
Caveat the podcast omits: independent benchmarks show Greptile has both the highest catch rate and the highest false-positive rate. Its own docs call the score a triage signal, not a rubber stamp — a high score means it found nothing concerning, not that nothing is wrong. Looping blindly to 5/5 can mean chasing phantom findings.
Cursor + frontier models the harness ✓ current

The harness wraps the model with tools, a system prompt, and config files. The podcast's stack: Cursor switching between GPT-5.5 (backend, "extra high" reasoning) and Opus 4.7 (UI, "max" reasoning).

  • Opus 4.7 shipped April 16, 2026 as Anthropic's flagship. GPT-5.5 is real; xhigh is a genuine reasoning-effort setting. "Opus 4.7 Max" = model + Cursor's max reasoning, not a separate model.
Unverified claim: the podcast asserts Cursor's harness benchmarks ahead of Claude Code and Codex on the same models. No source given — treat as a preference, not an established fact.
Convex backend as code ✓ positioning

Everything — schema, scheduled functions, APIs — is TypeScript code, so the agent has full backend context without screenshots of a dashboard. The dashboard is only for production setup and billing.

  • The "everything is code = full agent context" framing is accurate.
  • Tension with Supabase: Supabase mixes code with dashboard-managed config (RLS policies, etc.), so some backend state lives where the agent can't see it. That's the gap Convex argues against. Whether it's worth switching is a separate question — the context argument is the relevant one.
04

The one security tip worth adopting now

Tell your agent: never install a package younger than ~14 days.

Most supply-chain attacks are malicious package versions that drop and get caught within days. A 14-day floor means the vulnerability is usually flagged before you'd pull it. Directly relevant to automated pipelines (n8n, Supabase, GitHub Actions) where dependencies update without a human in the loop.

Adjacent verified-sensible advice: 2FA via an authenticator app, not SMS (SIM-swap is real); a password manager; and when a breach hits your feed, paste the details to your coding agent and have it check whether the affected package is in your project.

05

What to discount

The funnel

"Click the link, it's free, I'll email you everything" repeated ~6 times means the product is your email address. The content is the bait.

"Be delusional"

Survivorship bias. You hear about the delusional founders who shipped; not the larger number who shipped broken things and vanished. "Launch early, get feedback, iterate" is sound. "Believe your half-working MVP will change the world" is selection effect dressed as strategy.

Unsourced benchmark claims

Any specific "X beats Y" number stated without a citation — treat as vibes until verified.
